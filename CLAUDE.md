# cedar-in-privilege-LAB

Demo-tier standalone: "Cedar in Privilege", a guided tour of how Cedar AI policies work in PingOne Privilege, with three simulated cases (hold for a human, token-scope gate, agent act.sub gate), a "Set up Cedar in Privilege" guide (8 console steps) and a Cedar IS / IS NOT panel. Structure copied from cedar-act-sub-LAB (the lab with the owner-run real probe for the act.sub case).

- Run: `npm ci && npm start` (port 7820 and catalog id D135 are provisional placeholders; the shelf registry has the final say) or `docker compose up --build -d`
- Test: `npm test` (node --test + vitest + repo checks), `npm run doctor`. There is NO real probe here: Real is not available in this lab.
- Rules that bite: mock by default; the Real toggle is DISABLED with a visible reason and `POST /api/mode {"source":"real"}` answers 409 (the server never calls out; netguard + self-test stay on). The reason points, as plain text, to the owner-run probe in cedar-act-sub-LAB (`npm run real` there) and to the Privilege AI Policies and PingFederate Token Demo pages of the full demo app. Loopback-only publish, example ids only (`agent-client-example`, `agent-b-example`, `approver-example`, `door-example`, example scopes, `.example` hosts), the mock token of a run is shown whole and labelled mock-issued (rule 4). Never write a real tenant id, client id, host or customer name; never name the full demo app by its repo name (`scripts/repo-checks.mjs` forbids it).
- The mock door (`server/src/cedar.js`) evaluates THREE rule shapes: `hold` (mcp:InvokeUnattended, unless approval_count >= 1), `scope` (mcp:Invoke, unless token scopes contain the scope), `actsub` (mcp:Invoke, unless act.sub contains the agent). It is not a Cedar engine and decides nothing real; say so wherever it is described. A call carries one action, only policies naming that action apply, only Active policies are enforced, matching is exact. Scenario data, the three cases and the static measured evidence live in `server/src/scenarios.js`; the 8-step guide and the IS / IS NOT panel in `server/src/guide.js`.
- Honesty (rule 2): ONLY the act.sub case has a measured result (2026-11-16, one real agent, two Active policies, one refusal -32600, one first poll about 7 seconds after creation: one observation, not a propagation time). The hold and scope cases are SIMULATED; their shapes are console text recorded in the full demo app's notes, not re-run here. Every statement on the page is labelled measured / console text / UNVERIFIED. Unmeasured and labelled so: the hold's reply (HTTP 202 and body), how the gateway tells an unattended call apart, how a PingFederate token's scope reaches the policy, act as text, the no-token wording, Candidate not enforced (console documentation), RequiredClaims, exact vs substring matching, HTTP 400 for a refusal. Never write "verified", "validated", "never matches", "Cedar has no regex" or "a different agent was refused", and never call the hold or scope cases measured; `test/honesty-text.test.js` fails on them.
- What the mock door did (Rule 25; the panel is titled "What the mock door did (simulated)" through its title/basisNote props in `web/src/LabTrace.jsx`, never the default "What Privilege did", and `.lab-trace .gw-lead` is hidden in `web/app.css` because the panel is byte-pinned): `POST /api/run` attaches a `trace` per gateway call (`server/src/cedarTrace.js`, decisions `checked` because `callTool` computed them; a check an earlier refusal never reached is `skipped`; a hold is an `info` decision, never a pass). A simulated human approval is a step of its own with no trace. Vendored byte-for-byte, each with a pin file: `web/src/top-menu/*` (top-menu.sha256), `web/src/components/JsonPane.*` and `VerifyMark.*` (their .sha256), `web/src/gateway-trace/*` and `server/src/gatewayTrace.js` (gateway-trace.sha256), `web/standalone-ui.css` (scripts/standalone-ui.sha256), `test/kit/demo-kit-conformance.mjs` (test/kit/demo-kit-conformance.sha256), `scripts/check-no-ai-attribution.sh` (scripts/check-no-ai-attribution.sha256). Never hand-edit a pinned file; re-vendor with cp, then re-pin.
- The diagram (rule 17) is the diagram-studio repo's own flow (`CEDAR_IN_PRIVILEGE_FLOW`, id `cedar-in-privilege-flow`), vendored byte for byte in `web/src/studio-data/` with `studio-data.sha256` (re-vendor from the studio, never edit; the pin names the studio pull request branch until it merges) and looked up by name (`getDiagram`, `web/src/diagram-data.js`); there is no lab-local diagram file. Simulate finds arrows by the boxes they join; hold is the warning colour, refusal the accent. The page never throws on an unreachable server: `postJson` answers status 0 and the page shows the error with a Retry.
- Workspace id (rule 13): the `X-Workspace-Id` request header (1 to 64 of `A-Za-z0-9._-`, else a 400 `bad_workspace`; absent means `default`) keys `state.workspaces` in `server/src/index.js`, so runs and Reset are per visitor (at most 100 workspaces, least recently used dropped). `web/src/api.js` makes one id per tab, keeps it in `sessionStorage` (in memory if blocked) and sends it on every request, also to `/api/shelf` through ShelfLink and VerifyMark's `headers` prop. Never show it, never log it as a secret (it is not one). There is no trace sink: traces live in the run records.
- customer.config (rule 12): the optional `customer.config.json` is read by `npm start` / `npm run dev` only; the Docker image does not contain it (`.dockerignore`, read-only filesystem). The vendored trace panel keeps some generic headings ("Request sent to the gateway", "Decisions the gateway made"): do not edit the pinned file; fix upstream and re-vendor.
- Header controls: Help, version, Shelf and Talk track come from the shared TopMenu props. The dialogs are vendored byte for byte, each with its pin file: `web/src/floating-dialog/*`, `web/src/help-dialog/*`, `web/src/talk-track/*` and `web/src/components/ShelfLink.jsx` (`ShelfLink.sha256`); `test/vendored-pins.test.js` and `scripts/repo-checks.mjs` check them. The lab supplies only content: `web/src/helpContent.js` (Help) and `docs/talk-track.md` read at build time by `web/src/talkTrack.js` (a test fails when the doc's shape changes). The version is package.json's, set at build time by `vite.config.js` (`__LAB_VERSION__`). The Shelf link shows only when `/api/shelf` answers a `shelfUrl` (SHELF_URL, or the shelf behind the lab-proxy); the lab works with no shelf.
- Story mode (shared/story/README.md in AI-DEMO-Standalone): the wording is `video/captions.md` (written from `docs/talk-track.md`), served at `GET /api/story` (the shared parser, vendored in `server/src/story/` and `web/src/story/`, pinned and checked by `node scripts/story-checkPin.mjs .` / `test/story.test.js`). Vendored byte-for-byte from AI-DEMO-Standalone `shared/story` at commit `d349abf`; never hand-edit a vendored copy (re-vendor with cp, then re-pin with `node scripts/story-checkPin.mjs --write` in that repo). This lab has no Real mode: every step is Mock wording; runs announce `cip:run-start` / `cip:run-end` from `FlowSim`, reset announces `cip:reset`; the storage prefix is `cip`.
