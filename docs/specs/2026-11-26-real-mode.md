# Real mode, owner-gated — spec (both Cedar labs)

**Status:** draft · **Owner:** the repo owner · **Labs:** cedar-act-sub-LAB (primary), cedar-in-privilege-LAB (port)

## Goal
Turn the disabled "Real" option in each lab's Mode combobox into a working, owner-gated live mode: when the server finds a valid local `.env` (never in the Docker standalone), the UI's Simulate button runs the same read-only probe the terminal runs (`scripts/real-probe.mjs` logic) against the real PingFederate + Privilege door, and the page renders the verdicts inline, labelled REAL, next to the simulated runs.

## Design (agreed with owner)
- **UI Real mode, owner-gated.** Mode combobox enables only when the server reports real capability. The page drives the probe; no terminal needed.
- **The server reads `.env` and calls out ONLY on the owner's explicit click.** Default remains zero-outbound; container deployments (no `.env` mounted) are Mock-only by construction.
- **Reuse `real-probe-lib.mjs` untouched** (parseEnv, validateEnv, classifyVerdict, redact...). The server imports it; a new thin runner adds nothing the lib doesn't already shape.

## Acceptance criteria (runnable checks)
1. **No `.env`** → `/api/info` returns `realAvailable:false` with today's reason; Mode select disabled; behaviour byte-identical to current. (server test)
2. **Placeholder `.env`** (copy of `.env.example`) → same as (1); reason names `.env` needs editing. (server test)
3. **Valid `.env` present** → `/api/info` returns `realAvailable:true`; Mode select enabled; page shows a REAL-mode hint naming the issuer origin + door origin only (no values). (server test + browser)
4. **POST `/api/mode {source:"real"}` with valid `.env`** → 200, server mints a client-credentials token from `.env`, runs tools/list + CountTool + ListIndexTool (read-only), stores the last real result in memory (never written to disk), returns it. (server test against a local fake listener, like real-probe-e2e)
5. **POST `/api/mode {source:"real"}` without `.env`** → 409 `real_unavailable` (unchanged). (server test)
6. **UI: switch to Real, press a scenario's Simulate** → page shows the real verdicts (tools/list, CountTool, ListIndexTool) with a REAL label, the token's act shape, and the redacted reason for any refusal; mock sections stay visibly Mock. (browser, Playwright, against a fake door)
7. **Redaction** → every string the API returns passes through `redact()`; client secret / Basic value never appear anywhere in any response (test greps responses for the secret).
8. **Token display**: same policy as the probe — the access token may be shown (learning lab), labelled; secret never.
9. **Real run is read-only**: the runner performs exactly the 4 POSTs the probe does (token, tools/list, 2 tools/call). No other outbound from the server process. (test asserts outbound count/urls via fake listeners)

## Unhappy paths (each with a check)
- **No .env / placeholders** → criteria 1, 2; UI keeps Mock working.
- **Token endpoint down / timeout (15 s cap)** → 502 with redacted error; UI shows "real call failed" inline; mode stays Real but page works. (fake-listener test)
- **Door returns 401 / 403 / unreadable** → verdicts render as the probe classifies them (`token-rejected`, `refused-at-grant`, `unreadable`); run flagged "says nothing about the policy". (lib already tested; wire-through test)
- **Reply > 256 KiB** → capped, same as probe. (lib)
- **Repeated clicks** → each click runs a fresh probe; results replace, not append; no state file. (server test)
- **Docker standalone** → no `.env` in image/compose; assert compose file never mounts one. (repo test)

## Out of scope
- Real mode for hold/scope cases (case 1/2 real counterparts stay in the full demo app).
- Writing/deleting policies via the UI.
- Any change to `real-probe-lib.mjs` or the terminal probe's CLI behaviour.
- Storing real results across restarts.

## Protected / must not break
- Mock mode: byte-for-byte current behaviour when `.env` absent.
- `npm run real` CLI: unchanged output contract.
- Shared TopMenu byte-pinning (`standalone-ui.sha256`): if TopMenu changes, re-pin via the pinned script only.
- Security posture: secrets never logged/returned; outbound only to the two `.env` origins; `redirect:"error"`; 15 s timeout.
- Story mode + video pipeline merged today (PRs #12/#13, #17/#18).
